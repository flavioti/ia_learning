# Embedding Evaluation

How to verify the quality of an embedding. There is no universal "quality score": the best approach is to measure how the embedding behaves **in your task**. In [[RAG]], that is retrieval: does the embedding bring the right documents in the [[top-k]]?

## Recommended method: retrieval evaluation with your own dataset

1. **Build a golden set**: 50 to 200 real questions (or synthetic ones generated by an LLM) with the documents/products that should be returned.
2. **Run top-k search** with the candidate embedding.
3. **Compute the metrics** and compare models side by side.

| Metric | What it measures |
|--------|------------------|
| **Recall@k** | Did the correct item appear in the first k results? (most important in RAG) |
| **Hit rate@k** | Did at least one relevant item appear? |
| **MRR** | Position of the first relevant item |
| **nDCG@k** | Quality of the whole ranking, with relevance grades |
| **Precision@k** | How many of the k returned items are really relevant |

```python
def recall_at_k(results, relevant_ids, k=5):
    return len(set(results[:k]) & set(relevant_ids)) / len(relevant_ids)

scores = [
    recall_at_k(search(q, top_k=5), gold[q], k=5)
    for q in golden_questions
]
print(sum(scores) / len(scores))   # compare between models
```

## Other verification layers

| Layer | How | When |
|-------|-----|------|
| **Public benchmarks** | MTEB (general), MIRACL (multilingual) | To pre-select candidates. Does not replace your dataset |
| **Similarity sanity check** | Synonym pairs (high similarity) vs unrelated pairs (low) | Quick check, no dataset needed |
| **Visual inspection** | UMAP / t-SNE to see if items of the same category cluster | Exploratory |
| **End-to-end RAG evaluation** | Ragas, TruLens: context precision/recall, faithfulness | To know if the final answer improved |
| **LLM-as-a-judge** | A judge rates the relevance of returned items | When there is no labeled golden set ([[LLM-as-a-judge]]) |
| **Online metrics** | Clicks, conversion, "not found" rate | In production, with A/B test |

## What to compare

- Different models (e.g. `bge-m3` vs `text-embedding-3-small`), see [[Embedding Models and Algorithms]].
- Parameters: chunk size, dimension, `top-k`, [[Hybrid Search]] with BM25.
- With and without a reranker.

## Common pitfalls

- **Trusting only MTEB**: the general ranking may not reflect your domain and language.
- **Small or biased dataset**: use questions similar to real user questions.
- **Evaluating only the embedding**: chunking, filters and reranking affect the result as much as the model.
- **Forgetting to re-evaluate** when changing model or version.

## Practical summary

1. Pre-select 2 to 3 models using MTEB / MIRACL.
2. Measure **Recall@k and MRR** on your golden set.
3. Validate with end-to-end RAG evaluation.
4. Monitor online metrics after deploy.
