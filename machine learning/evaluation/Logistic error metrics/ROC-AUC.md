# ROC-AUC

## What is it?

**ROC-AUC** (*Receiver Operating Characteristic – Area Under the Curve*) is an evaluation metric for binary classification. It measures how well the model **ranks positive instances above negative ones**, across all possible decision thresholds.

- **ROC** = curve showing the trade-off between hits and false alarms
- **AUC** = area under the curve (0 to 1, higher is better)

---

## Quick Summary

```
ROC-AUC = 0.50  →  Random (model learns nothing) ❌
ROC-AUC = 0.70  →  Good (model discriminates) ✅
ROC-AUC = 0.90  →  Excellent (very good) ✅✅
ROC-AUC = 1.00  →  Perfect (practically impossible on real data) 🎯
```

---

## How the ROC Curve is built

The curve is drawn by sweeping the decision threshold from 1.0 down to 0.0 and plotting two values:

- **TPR** (True Positive Rate, also [[Recall]] or sensitivity), on the **y** axis:

  $$\text{TPR} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$

- **FPR** (False Positive Rate, or 1 − specificity), on the **x** axis:

  $$\text{FPR} = \frac{\text{FP}}{\text{FP} + \text{TN}}$$

As the threshold drops, more samples are classified as positive, and both true positives and false positives increase. The curve shows this trade-off at every threshold. All four counts come from the [[Confusion Matrix]].

## Interpreting the AUC

| AUC | Quality |
|-----|---------|
| **0.90-1.00** | Excellent |
| **0.80-0.90** | Very good |
| **0.70-0.80** | Good |
| **0.60-0.70** | Fair |
| **0.50-0.60** | Weak |
| **0.50** | Random (no value) |
| **< 0.50** | Worse than chance (usually means inverted labels or scores) |

These bands are rules of thumb. What counts as good depends on the domain.

### Probabilistic interpretation

The AUC is the probability that a randomly chosen positive sample gets a higher score than a randomly chosen negative sample:

$$\text{AUC} = P(\hat{y}_{\text{pos}} > \hat{y}_{\text{neg}})$$

Ties count as one half. This is equivalent to the Mann-Whitney U statistic normalized by the number of positive-negative pairs.

**Worked example** (the Python example below): positives have scores 0.8, 0.9, 0.7, 0.15 and negatives have 0.1, 0.2. There are 4 × 2 = 8 pairs, and the positive wins in 7 (only 0.15 loses to 0.2), so AUC = 7/8 = 0.875.

---

## Properties

| Property | Explanation |
|----------|-------------|
| **Threshold-independent** | Evaluates the overall ranking, without fixing a cutoff (e.g. 0.5) |
| **Scale-invariant** | Measures the ordering of predictions, not calibrated probabilities. Monotonic transformations of the scores do not change the AUC |
| **Not a calibration metric** | A model can have a high AUC and badly calibrated probabilities |
| **Fair comparison** | Allows comparing models on a single, threshold-free number |

---

## ROC-AUC vs Accuracy

| Metric | Uses | Problem |
|--------|------|---------|
| **[[Accuracy]]** | Fixed threshold (50%) | Misleading with imbalanced data |
| **ROC-AUC** | All thresholds | Shows the real ability to separate the classes |

**Example:** dataset with 95% negatives
- Model that always predicts "negative" → 95% accuracy ❌ (misleading!)
- Same model → ROC-AUC = 0.50 ✅ (reveals it is useless)

---

## Limitation: highly imbalanced data

With **severe imbalance** (e.g. fraud, rare diseases), ROC-AUC can give an **overly optimistic** impression.

The FPR denominator includes all true negatives (TN + FP). With a huge number of negatives, the FPR stays low even when the model produces many false positives relative to the small positive class.

**Example:** 100 positives and 100,000 negatives. At some threshold the model finds 80 positives (TPR = 0.80) with 1,000 false positives. FPR is only 1% (1,000 / 100,000), which looks great on the ROC curve, but [[Precision]] is just 80 / 1,080 ≈ 7%.

> **Rule of thumb:** with severe imbalance, prefer [[PR-AUC]] (area under the Precision-Recall curve), since Precision directly reflects false positives against the minority class.

---

## Multi-class

ROC-AUC is defined for binary problems. For multi-class, compute it one-vs-rest (OvR) or one-vs-one (OvO) and average (macro or weighted).

---

## Python example

```python
from sklearn.metrics import roc_auc_score, roc_curve

# After making predictions
y_true = [0, 1, 1, 0, 1, 1]
y_pred_proba = [0.1, 0.8, 0.9, 0.2, 0.7, 0.15]

roc_auc = roc_auc_score(y_true, y_pred_proba)
print(f"ROC-AUC: {roc_auc:.2f}")
# Output: ROC-AUC: 0.88

# Points of the curve (one per threshold)
fpr, tpr, thresholds = roc_curve(y_true, y_pred_proba)

# Multi-class (one-vs-rest), y_proba has shape (n_samples, n_classes)
# roc_auc_score(y_true, y_proba, multi_class="ovr", average="macro")
```

Pass probabilities or scores, not hard class labels: hard labels collapse the curve to a single point and discard the ranking.

---

## When to use?

✅ **USE:**
- Binary classification
- Comparing models
- Evaluating across different thresholds
- Data with moderate imbalance

❌ **DON'T use (or prefer another metric):**
- Regression (it is not classification)
- Severe imbalance, where [[PR-AUC]] is more informative
- When the threshold is fixed and important, or when calibrated probabilities matter

---

## Summary

**ROC-AUC = a robust metric of the ability to rank positives above negatives, regardless of the threshold used.** Under severe imbalance, also confirm with PR-AUC.
